# 기간 선택 과거 메일 가져오기 — 개발 예정

> 2026-11-24 사용자 결정 · **확정된 개발 예정, 미구현** · 이번 문서 작업에서 기능·DB·API를 구현하지 않음

## 목적과 기본 동작

기본 수신은 기존처럼 사용 시작 이후 도착한 INBOX 메일만 유지한다.
'과거 메일 없이 시작'은 기본 동작이지 과거 메일 가져오기 계획의 보류를 뜻하지 않는다.
사용자가 필요한 기간을 직접 고르고 명시적으로 실행할 때만 과거 메일을 가져오는 기능을 개발한다.
현재 화면·API·CLI에는 이 기능이 없으므로 계정 시작 시점·수신 커서·DB를 수동 수정하지 않는다.

## 확정 범위

- 가져올 기간을 선택하고 범위·양을 확인한 뒤 명시적으로 시작한다. 설치·연결만으로 자동 실행하지 않는다.
- 기존 계정·OAuth/API/AI 키·메일·분석 결과를 보존한다. 중복 저장을 방지한다.
- 진행 상황·중단·실패 후 재시도를 제공한다. 부분 완료와 오류를 구분하고 이미 저장한 자료를 잃지 않는다.
- 가져온 메일은 **로컬 AI**로 분석하고 검색·보고서에 연결한다.
- 가져오기 자체로 Claude를 자동 호출하지 않는다. 이후 사용자가 F2/F3/F4에서 별도로 Claude를 선택할 때는
  기존 외부 전송 동의·자료 종류·API 요금 안내를 그대로 적용한다.
- 현재 앱·서버·PostgreSQL 구성에서 개발한다. 클라우드 이전의 선행 조건으로 묶지 않는다.

## 통합 개발 전에 구체화할 계약

기간의 시간대·끝 경계, INBOX/보낸 메일 등 대상 범위, 건수·용량 상한, 진행 상태 저장·중단·재시작,
계정별 동시 실행, 기존 시작 시점 제한과 가져온 메일의 검색/보고 범위, 중복 분석 방지·재분석 정책을 확정한다.
현재 저장·검색·보고 계층이 `sync_started_at` 이전을 막으므로 UI만 추가해 완료 처리할 수 없다.
API/마이그레이션은 아직 정의·예약하지 않았으며 공통 규칙에 따라 통합 채팅에서 설계한다.

## 향후 수용 기준

- [ ] 기간 선택과 명시적 시작 없이 과거 메일을 수집하지 않는다.
- [ ] 기존 계정·키·메일·기본 수신 시작 시점을 보존한다.
- [ ] 같은 범위 반복·실패 후 재시도·중단 후 재개에도 메일 중복/누락이 없다.
- [ ] 진행·부분 완료·실패·중단을 구분해 표시한다.
- [ ] 로컬 분석 결과가 검색·보고 입력에 포함되며 소유 계정·기간·근거가 유지된다.
- [ ] 키·본문을 로그에 남기지 않고 가져오기만으로 Claude를 호출하지 않는다.
