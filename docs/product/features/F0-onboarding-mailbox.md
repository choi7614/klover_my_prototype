# F0. 첫 실행 설정과 기본 메일함

> 현재 기준: `develop 5e2b7a7`(PR #38) + 통합 작업 브랜치(반영 승인 대기), 2026-11-24. 목록·본문·새로고침·분석 표시·다른 기능 화면/IPC는 구현되어 있다. Google 연결은 CLI이며 앱 연결/다음 버튼·5단계 완료·쓰기·트레이는 미구현이다.

## 1. 목적

Klover는 Gmail을 **대체하는** 메일 앱이다. 사용자는 처음 실행할 때 5단계 설정을 거친 뒤, 기본은 과거 메일 없이 시작하며, 연결 이후 도착한 INBOX를 받는다. 기간 선택 과거 메일 가져오기는 통합 작업 브랜치에 구현됐고 자동 검사 완료·실제 Gmail 미검증이다. 이후 작성·보내기·보관·삭제·스팸 등 기본 메일 기능을 모두 Klover 안에서 쓴다.

AI 기능(F1~F5)은 이 기본 메일함 위에서 동작하므로, F0는 모든 기능의 바닥이다.

## 2. 사용자 시나리오

### 2-1. 첫 실행 (5단계 마법사)

1. **Gmail 계정 연결** — Google 로그인(OAuth)으로 Gmail 권한을 받는다. 연결된 계정 이메일을 표시한다.
2. **프로필 입력** — 이름, 직급, 소속, 담당 업무를 입력한다. (F2 프로필과 같은 데이터)
3. **문체 학습 동의** — "이 앱에서 보낸 메일의 표현과 문장 습관을 분석해 답장 초안에 반영합니다. 설정에서 언제든 끄고 학습 기록을 삭제할 수 있습니다." 안내 후 동의를 받는다.
4. **알림과 시작 프로그램**
   - Windows를 켜면 Klover 자동 실행 (기본 켬)
   - 창을 닫아도 트레이에서 계속 실행 (기본 켬, 완전 종료는 트레이 아이콘 → '종료')
   - AI 제안을 즉시 알림으로 받기 (기본 켬) + 유형 선택: 일정 등록 / 할 일 / 회신 필요 / 결재·승인 / 중요 발신자
   - 일정을 등록할 캘린더: Google Calendar 연결 상태 표시
   - 안내 문구: "앱이 꺼져 있던 동안 생긴 제안은 다음 실행 때 모아서 보여드립니다."
5. **완료** — 받은편지함으로 이동한다.

### 2-2. 빈 받은편지함

- 가운데에 "받은편지함이 비어 있습니다 / 지금부터 도착하는 메일을 AI가 분석합니다. 이전 메일은 가져오지 않습니다." 안내와 [새 메일 쓰기] 버튼
- 하단에 **기능 준비 상태** 표시

| 기능 | 상태 문구 |
| --- | --- |
| AI 분류·AI 스캔 알림 | 바로 사용 |
| 답장 초안 | 바로 사용 (문체 설정 기준) |
| 자연어 검색 | 메일이 쌓이는 대로 |
| 주간 보고 | 첫 주도 시작일부터 오늘까지 확보된 분석 자료로 생성 (PR #37) |
| 문체 학습 | 보낸 메일이 쌓이는 대로 |

### 2-3. 기본 메일 기능

- 화면 구조: 3단 — 왼쪽 사이드바 / 가운데 메일 목록 / 오른쪽 메일 읽기
- 상단: [새 메일] 버튼, 자연어 검색창(F3로 연결), 계정 이메일
- 사이드바 메일함: 받은편지함(안 읽은 수), 보낸편지함, 임시보관함, 보관함, 스팸·휴지통
- 사이드바 스마트 보기·AI 카테고리는 F1, '도구'(주간 보고, 설정)는 F4·F2에서 정의
- 메일 읽기 영역 버튼: [답장 초안 만들기] (F2), [답장], [보관], [삭제], [할 일 추가] (F5)
- 메일 작성: 받는 사람, 참조, 제목, 본문, 첨부, [임시 저장] [보내기]

## 3. 동작 규칙

- 기본 동기화는 **Klover 사용 시작 이후 INBOX 메일만**이다. 자동으로 과거 메일을 수집하지 않으며, 기간 선택·명시적 실행·진행/중단/재시도를 갖춘 [과거 메일 가져오기](planned-mail-history-import.md)는 명시적으로 실행하는 기능으로 구현됐다(develop 반영 승인 대기). 기존 계정·키·메일·중복 방지를 보존하고 로컬 분석 후 검색·보고에 연결하며, 가져오기만으로 Claude를 자동 호출하지 않는다.
- 메일 계정 접근(읽기·보내기·보관·삭제)은 **서버가 담당**한다. 앱은 서버 API만 호출한다.
- 사용자가 보관한 메일은 사용자가 삭제할 때까지 서버에 유지된다(메타데이터·벡터 포함).
- 트레이 상주: 창 닫기(X) = 트레이로 숨김. 트레이 메뉴: 열기 / 종료.
- 시작 프로그램 등록은 설정에서 켜고 끌 수 있다.
- 설정 마법사를 중간에 끄면, 다음 실행 때 마지막 단계부터 이어서 한다.

## 4. 데이터·API

- `POST /auth/google` — OAuth 코드 교환, 서버가 토큰 저장
- `GET /mails?box=inbox&cursor=` — 메일 목록
- `GET /mails/{mail_id}` — 메일 상세
- `POST /mails/sync` — Gmail 새 받은 메일 가져오기 (앱 새로고침, 사용 시작 이후·중복 제외)
- `POST /mails/send` — 메일 보내기 (보낸 메일은 F2 문체 학습 대상)
- `POST /mails/{mail_id}/archive` / `DELETE /mails/{mail_id}` / `POST /mails/{mail_id}/spam`
- `PUT /settings/notifications` — 알림·시작 프로그램 설정
- 메일 데이터 구조: `docs/architecture/data-model.md`

## 5. 수용 기준

### 초기 구현 기록 (2026-11-18~19, 현재 연결 상태는 상단 status 참조)

1. **앱 실행 기반·첫 실행 시작 화면** — 이번 단위. Electron·React 실행, S01의 5단계 표시와 첫 화면, 연결 전 다음 진행 차단, 실행·화면 테스트를 구현한다.
2. **실제 서버 연결·설정 완료·빈 메일함** — 서버 기반과 OAuth 요청·응답·인증 복귀 방식, 프로필·알림 설정·메일 조회 API를 준비한 뒤 진행한다.
3. **기본 메일 처리** — 사용 시작 이후 메일 조회, 작성·발송, 보관·삭제·스팸을 나누어 구현한다.
4. **Windows 동작** — 트레이 상주·종료·자동 실행을 Windows에서 검증한다.

당시 첫 단위에는 Google OAuth·메일 API 연결부가 없었다. 현재 메일 API 연결은 구현됐고 앱 안 Google 버튼 연결은 남아 있다. 공통 HTTP 서버의 `/health`는 계정 연결을 제공하지 않는다. 첫 단위에서는 가짜 로그인·메일 서버를 만들지 않으며 Google 연결과 다음 버튼을 비활성으로 표시한다.
첫 수용 기준 전체(5단계 완료·재실행)는 아직 미완료이므로 아래 체크를 유지한다.

2026-11-19: 별도 맥북 로컬 서버의 Google 로그인·동의·계정 확인·토큰 암호화 저장을 준비했다.
F0 데스크톱의 Google 버튼은 아직 이 흐름에 연결하지 않았다. 사용자는 별도 맥북 연결 화면에서
실제 로그인 성공 및 CLI의 새 메일 1건 저장·조회·재수신 중복 방지를 확인했다.
토큰 갱신은 자동 검사만 완료했다. 로컬 API 인증·계정·목록·텍스트 본문 조회를 서버에
구현했다. 이후 F0 연결·IPC는 병합됐으며 실환경 종합 검증은 별도다.
아래 앱의 Gmail 로그인·받은편지함 수용 기준은 아직 완료로 바꾸지 않는다.

기존 첫 화면을 보존하고 연결된 계정의 받은편지함을 연다.

사용 시작 시점 이후만 받는 규칙과 중복 방지는 기존 수신 기능(CLI `gmail_mail sync`와 같음)을 따른다.

## 7. 결정 사항 / 남은 확인 포인트

**결정 사항**

- Gmail을 대체하는 메일 앱 (작성·보내기·보관·삭제·스팸 포함)
- 과거 메일 없이 빈 상태로 시작
- 첫 실행 때 문체 학습 동의
- 시작 프로그램 등록, 트레이 상주, 즉시 알림이 기본값

**남은 확인 포인트**

- Gmail에 이미 있는 메일이 앱에서 보이지 않는다는 점을 사용자에게 어떻게 안내할지
- 앱에서 보관·삭제하면 Gmail 쪽에도 똑같이 반영할지
- 기존 Gmail 라벨을 함께 보여 줄지
- 보관하지 않은 메일을 서버에 얼마나 보관할지
