## 현재 단계와 반영 순서

현재 원격 main은 초기 `9575f47`이며 실행 코드가 없다. **이번 문서는 main 반영 후의 설치 안내를 준비한 상태**다.
결과 보고 후 문서 커밋·Push·develop/main 대상 PR 생성과 검사 통과 시 develop 병합을 승인받았다.
main 병합은 별도 승인 대기이며 최종 반영 상태는 각 PR 이력을 따른다.

1. 결과 보고 후 문서 변경의 커밋·Push·develop 대상 PR 생성 묶음 승인.
2. 별도 develop 병합 승인 후 준비 문서 반영.
3. 최신 develop을 main 대상으로 PR 생성하고 고정한 커밋의 코드·문서·CI 확인.
   이 PR 생성도 묶음 승인 범위에 명시하며 main 병합 승인을 대신하지 않는다.
4. **main 병합 별도 승인** 후 반영. main의 README·설치 파일 존재와 병합 결과 확인.
5. 동료에게 저장소 첫 화면 URL과 main의 코드 버전을 전달.

main은 현재 develop의 조상이다. main 반영 PR은 문서 몇 개만이 아니라 develop에 누적된 앱·서버·DB·기능 전체를 포함한다.
초기 공유는 소스 실행용 데모이며 설치형 제품·모든 OS 실기 검증 완료로 소개하지 않는다.
초대·공개 상태 변경·기존 작업/브랜치 삭제는 이번 범위에 없다. 원격 조회 당시 저장소는 공개 상태다.

- [쉬운 구성도](../architecture/overview.md): 사용자별 PC·서버·DB·Google·로컬 AI·선택적 Claude의 관계와 데이터 위치 설명.
- 시스템/DB 구조의 오래된 Calendar 미구현·마이그레이션 안내 정정.
- 현황판·통합 후속 목록 갱신. 제품 코드·DB 이력·실행 도구·의존성 잠금 파일은 변경하지 않았다.

## 실제 PC에서 남은 확인

1. 동료 본인의 새 폴더에서 main을 받아 본인 Google 프로젝트·OAuth·로컬 DB·모델을 준비.
2. 최초 로그인 후 더블클릭 시작 → 목록/본문 → 새로고침/분석 → 프로필/초안 → 검색 → 첫 주 보고 확인.
3. 앱 종료 후 이번 서버가 정리되고 재실행 시 기존 메일·프로필이 유지되는지 확인.
4. 선택한 경우만 실제 Claude 키·연결/비용·외부 전송과 별도 테스트 Calendar 동의/승인 등록 확인.

이 환경은 동료 Mac/Windows 기기를 대신하지 않는다. 실제 Finder/탐색기부터 앱까지의 새 설치 전체 흐름,
Windows 비밀 파일 ACL, 실제 모델 품질/속도, 실제 Google·Claude는 미검증이다.
운영 DB 초기화·실제 데이터 삭제·회사 자료 전송으로 확인하지 않는다.

영상 녹화는 사용자가 진행한다. 합성 메일을 사용하고 로그인·키·인증 주소·개인 메일·알림은 가린다.
