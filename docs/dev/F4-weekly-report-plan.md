> 확인일: 2026-11-12 · 브랜치: `feat/F4-weekly-report`

## 현재 기반

`develop`의 `9575f47`에는 문서와 HTML·PNG 목업만 있다. `apps/desktop`,
`apps/server`, `packages`, `fixtures`, `infra`와 실행·테스트 설정은 없다.
메일 DB·조회 API, F1 분석 결과, F2 프로필, 보고서 API, AI 호출 인터페이스도
구현되어 있지 않다. API 문서의 경로는 설계 목록이지 사용 가능한 API가 아니다.
원격에는 F4 브랜치가 없어 위 커밋에서 기능 브랜치를 만들었다.

F4 정의서와 S08 정의서·목업을 기준으로 아래 순서로 진행한다. 이번 변경은
첫 단위인 **보고 입력 준비**까지만 구현한다.

Word 내보내기와 메일 작성 창 연계는 원 명세에 있는 후속 항목이며 이번
첫 단위에는 포함하지 않는다. 자동 발송·예약 생성·메일 외 데이터는 구현하지 않는다.

## 첫 단위의 내부 계약

- `app.services.report.prepare_weekly_report_input`은 메일 저장소 인터페이스를
  주입받는다. 실제 DB 조회는 추후 B의 저장소 구현으로 연결한다.
- `start`, `end`는 Asia/Seoul의 날짜이며 양 끝 날짜를 포함한다. 저장소 조회는
  시작일 00:00 이상, 종료 다음 날 00:00 미만으로 한다. 시각에 시간대가 없으면
  입력 검증에 실패한다. 발신 메일도 데이터 모델의 `received_at`(발신 시각)을 쓴다.
- 로그인 사용자의 `user_id`로 조회하며 다른 사용자의 메일은 포함하지 않는다.
  CLI의 사용자 ID 인자는 개발용이다. HTTP 인증을 대체하지 않는다.
- 유효 분류는 `user_label`이 있으면 그 값, 없으면 `category`다. `notice`,
  `newsletter`는 제외 목록에 원문 정보와 사유를 남긴다.
- 그 밖의 메일 중 F1 분석이 `pending`/`failed`이거나 분류가 없으면 준비 실패로
  알린다. 이 메일을 제외 건수로 숨기거나 임의 분류·요약하지 않는다.
- 같은 스레드 또는 같은 프로젝트를 공유하는 메일을 연결해 업무 그룹으로 묶는다.
  조직·사람 이름만 같은 메일은 합치지 않는다. 키가 없는 메일은 단독 그룹이다.
  제외 메일은 그룹을 연결하는 데 쓰지 않는다.
- 메일은 시각·ID 순, 그룹은 첫 메일 순으로 정렬한다. 각 그룹의 `mail_ids`가
  다음 단위에서 허용할 근거 ID의 원천이다. 이 단계는 보고 항목을 작성하지 않는다.
- `scope.total = scope.grouped + scope.excluded`이며 `grouped`는 중복 없는
  메일 수, `groups`는 업무 그룹 수다. 데이터가 없으면 모두 0이다.

## 실행과 검증

[setup.md](setup.md)의 F4 명령을 사용한다. JSON fixture는 `synthetic: true`로
명시한 가짜 메일이며, CLI에서 `--fixture`를 지정할 때만 읽는다. 기본 데이터
소스나 실제 서버로 자동 연결하지 않는다.

이번에는 HTTP 엔드포인트·DB 테이블·AI 구현·데스크톱 화면을 추가하지 않는다.
따라서 OpenAPI/TypeScript 타입 생성 대상도 없다. 실제 DB·F1·F2·AI와의 통합은
아직 검증할 수 없으며 다음 단위의 선행 조건이다.

## F4 수용 기준 추적

2026-11-12 검증: pytest 21개 통과, Ruff lint·format 검사 통과. fixture CLI 결과는
전체 12건 = 묶인 9건 + 제외 3건, 업무 6개다. 한국 시간의 양 끝 날짜, 발신 메일,
사용자 분리, 분류 수정, 전이적 그룹 연결, 제외 메일에 의한 오연결 방지, 분석
미완료·빈 데이터·중복 ID·저장소 계약 위반을 확인했다.
