# 도구 전환용 프롬프트 모음 (Codex ↔ Claude)

> 규칙: [AGENTS.md](../../AGENTS.md)의 '도구 전환과 인수인계' · 현황판: [progress.md](progress.md)

아래 프롬프트를 채팅 창에 그대로 붙여 쓴다. `{ }` 부분만 바꾼다.

| 바꿀 값 | 예시 |
| --- | --- |
| `{기능}` | `F3` |
| `{브랜치}` | `feat/F3-search` |
| `{status}` | `docs/dev/F3-search-status.md` |
| `{도구}` | `Codex` 또는 `Claude` |

---

## 1. Codex 복귀 시 (한동안 Claude만 쓰다가 Codex로 돌아올 때)

```text
[{기능} 채팅 · Codex 복귀]
choi7614/klover_my_prototype 저장소에서 작업을 다시 시작한다. 파일은 아직 수정하지 마.
1. git fetch origin 후 현재 브랜치, {브랜치}의 로컬·원격 차이, 미커밋 변경을 확인해줘.
2. 최신 origin/develop의 AGENTS.md를 읽고, 내가 기억하는 규칙에서 바뀐 점(특히 인수인계·공통 영역·승인 규칙)을 요약해줘.
3. {브랜치}에 최신 origin/develop이 반영돼 있는지(뒤처진 커밋 수) 알려줘.
4. docs/dev/progress.md에서 {기능} 행과 '작업 도구'를 확인하고, 다른 도구가 작업 중이면 멈추고 알려줘.
5. {status}의 양식 요약·다음 할 일·인수인계 메모를 읽고 이어서 할 일을 제안해줘.
6. 문제가 없으면 progress.md의 {기능} 행을 작업 도구=Codex, 갱신일=오늘로 바꾸는 변경만 준비하고 보고해줘.
develop 반영(로컬 통합)이 필요하면 가져올 브랜치·적용할 브랜치를 보고하고 묶음 승인을 받아줘.
```

## 2. 한도 직전 긴급 [WIP] 저장

```text
[긴급 · {기능} WIP 저장]
사용 한도로 곧 끊길 수 있다. AGENTS.md의 '사용 한도로 끊길 위험이 있을 때' 규칙대로 지금 바로 저장해줘.
- 대상 브랜치: {브랜치} (develop·main이면 멈추고 알려줘)
- {status}의 '인수인계 메모'에 멈춘 지점·실패/미실행 검사·다음 할 일을 3~5줄로 적어줘.
- docs/dev/progress.md의 {기능} 행: 상태=WIP 저장, 작업 도구=없음, 마지막 커밋·갱신일 갱신.
- .env·키·토큰·실제 메일이 스테이징되지 않았는지 확인.
- 커밋 메시지 "[{기능}][WIP] 인수인계: 멈춘 지점 한 줄" 로 커밋하고 {브랜치}에 Push.
검사 통과는 기다리지 않는다. PR 생성·병합은 하지 마. 끝나면 커밋 해시만 짧게 알려줘.
```

## 3. 정상 인수인계 (다른 도구로 넘길 때)

```text
[{기능} 채팅 · 인수인계 준비]
지금 작업을 {도구}(으)로 넘기려고 한다.
1. 현재 작업 단위를 마무리할 수 있으면 마무리하고, 못 하면 멈춘 지점을 정리해줘.
2. 관련 검사(서버 ruff·pytest, 데스크톱 lint·typecheck·test 중 해당하는 것)를 실행하고 결과를 구분해서 적어줘.
3. {status}를 docs/dev/status-template.md 양식대로 갱신: 양식 요약·현재 상태·검사 결과·다음 할 일·인수인계 메모.
4. docs/dev/progress.md의 {기능} 행: 작업 도구=없음, 상태·마지막 커밋·다음 할 일·갱신일 갱신.
5. 미커밋 파일이 남지 않게 변경 파일·검사 결과를 보고하고 커밋·Push(필요하면 PR)를 묶음 승인받아줘.
develop 병합은 하지 마.
```

## 4. 다른 도구에서 이어받을 때

```text
[{기능} 채팅 · {도구}에서 이어받기]
{브랜치}를 이어받는다. AGENTS.md의 '이어받을 때' 순서대로 확인만 먼저 하고 보고해줘. 파일은 아직 수정하지 마.
1. git fetch origin → {브랜치} 로컬·원격 차이, origin/develop 대비 뒤처짐
2. docs/dev/progress.md의 {기능} 행 (작업 도구가 '없음'이 아니면 멈추고 알려줘)
3. {status}의 양식 요약·다음 할 일·인수인계 메모
4. 미커밋 변경과 [WIP] 커밋 여부 (git status, git log origin/develop..origin/{브랜치})
5. AGENTS.md가 마지막으로 바뀐 커밋
보고 후, 이어서 할 작업 단위를 제안하고 progress.md 작업 도구를 {도구}(으)로 바꾸는 것부터 시작해줘.
```

## 5. 통합 점검 (통합 채팅)

```text
[통합 채팅 · 통합 점검]
choi7614/klover_my_prototype의 통합 상태를 점검한다. 파일은 아직 수정하지 마.
1. git fetch origin 후 모든 feat/ 브랜치의 develop 병합 여부·뒤처짐·열린 PR 목록
2. docs/dev/progress.md와 실제 저장소 상태(브랜치·마지막 커밋·PR)가 맞는지 비교
3. 작업 도구가 '없음'이 아닌 행, WIP 저장 상태인 행
4. 적용 대기 중인 공통 영역 패치(patches/, integration/)와 마이그레이션 번호 예약 표의 충돌 여부
5. 최신 develop에서 서버 ruff·pytest, 데스크톱 lint·typecheck·test 결과 (DB 필요 검사는 skip 여부 구분)
점검 결과를 쉬운 말로 요약하고, 통합 순서(어떤 패치를 어떤 순서로 적용할지)를 제안해줘.
적용·커밋·Push·PR은 묶음 승인 후, develop 병합은 별도 승인 후에만 진행해.
```
