# F5 구현 계약과 실행 경계

통합 기준: `origin/develop` b147cfd. F5 전용 코드와 합성 데이터 검사를 구현했다.
사용자 승인으로 공통 서버 등록·0005_f5 DB 이력·공유 타입을 적용했다. 운영 DB 실제 적용과
F1 입력 변환·F0 연결은 별도다. 기존 F2·F3 구조와 경로를 유지한다.
실제 Gmail 계정·OAuth 범위·키·메일·수신 커서는 읽거나 변경하지 않는다.

## F1 → F5

`ScanInput`(`f1.scan-input.v1`)은 내부 서비스 입력이며 HTTP로 외부에 노출하지 않는다.
F1의 공통 AI 호출부를 재구현하지 않는다. F1 어댑터가 원본 `mail_id`,
저장된 `body_text`의 UTF-8 SHA-256, `events`, `action_items`, 선택적 `reply`를 전달한다.
각 행동에는 재분석에도 유지하는 `action_key`와 하나 이상의 근거 위치가 필요하다.
위치는 **Unicode 코드 포인트, 시작 포함·끝 제외**다. HTML·정규화된 다른 본문 기준이 아니다.
각 근거의 `mail_id`, 범위, `quote == body_text[start:end]`를 모두 검증한다.
화면의 JavaScript UTF-16 위치와 혼동하지 않도록 코드 포인트 배열로 렌더링한다.

소유자·계정은 신뢰한 작업 컨텍스트/기존 인증 세션에서만 받는다. 실제 메일 소유자와
사용 시작 시점 이후 받은 메일인지 다시 확인한다. 본문 해시가 바뀐 입력은 거부한다.
같은 메일·유형·action_key 또는 같은 근거 위치의 재입력은 기존 제안을 반환한다.
최초 저장값·사용자 처리 상태를 보존하고 이벤트를 다시 만들지 않는다.
같은 문장 속 서로 다른 같은 유형 행동은 **서로 다른 정확한 근거 범위**를 전달해야 한다.
기존 행동의 교체·철회와 본문 변경 후 자동 재생성은 별도 합의가 필요하다.

## 상태·실행

업무 상태는 `pending|approved|dismissed`다. 별도 `execution_status`로 준비·진행·실패·
결과 불명확·테스트 실행을 구분한다. `approved`는 내부 할 일 저장 또는 실제 실행 영수증을
받은 경우에만 가능하다. Calendar 테스트 결과는 `pending + simulated + test`이며 성공으로 표시하지 않는다.
F2 초안 실행기가 없으면 회신 제안 승인은 차단한다. 메일 발송 경로는 없다.

승인·무시·할 일 수정에는 `version`을 보낸다. 승인 시 최신 행을 잠그고 실행 권한을
확보한 뒤 외부 호출 전에 확정한다. 동시 승인은 하나만 실행한다. 성공한 동일 요청은
저장된 결과를 재사용한다. 불명확한 Calendar 요청의 입력은 고정하며 수정해서 재시도할 수 없다.
Calendar event ID는 제안별 결정적 ID이며, 재시도는 조회 후 같은 ID로만 삽입한다.
프로세스가 실행 중 종료되면 `executing`은 자동 해제하지 않는다. 담당자가 동일 event ID로
조회·조정해야 한다. 외부 시스템과 DB 사이의 분산 트랜잭션을 보장한다고 주장하지 않는다.

## Calendar 권한·오류

기본 실행기는 항상 차단된다. Google 어댑터는 명시적인 소유 계정·실제 동의 범위와
주입된 transport가 있어야 한다. Gmail 읽기 권한이나 콘솔 API 활성화는 Calendar 동의가 아니다.
이번 코드에는 실제 HTTP transport·토큰 로더·재동의 절차가 없다.
쓰기와 freebusy 권한을 각각 검사한다. freebusy에는 제목이 없으므로 이름을 지어내지 않는다.
인증/권한/연결 불가, 확실한 실패, 전송 후 타임아웃을 구분한다. 외부 오류 원문을 응답·로그에 넣지 않는다.

## 알림·API

F5 라우터는 공통 앱과 테스트 앱에 등록한다. 기존 인증 의존성을 재사용하며 클라이언트가
`user_id`/`account_id`를 지정할 수 없다. 개인 응답과 오류는 `no-store`다.
`GET /suggestions?status=pending&notified=false`는 놓친 제안을 조회만 한다.
제안 생성과 동일 트랜잭션에 유일한 `suggestion.created` outbox 이벤트를 저장한다.
이벤트 조회는 읽기만 하며, F0가 실제 표시 후 ack할 때만 `notified_at`을 기록한다.
이벤트 재전달 시 F0도 `event_id`를 영구 중복 제거해야 한다. 네트워크에서 정확히 1회 표시를 보장하지 않는다.
무시·완료한 제안은 이벤트와 놓친 목록에서 제외된다. 유형 설정·메일별 묶음·빈도 제한은 F0 연결 요청 대상이다.

할 일은 직접 생성 또는 제안 승인으로 생성한다. 제안 승인과 할 일 생성은 원자적이며
제안당 하나만 존재한다. 직접 생성은 `request_id`로 재시도 중복을 막는다.
리마인더 스케줄러·스마트 보기 건수 연결은 아직 없다.

## 화면과 확인 범위

기능 전용 S04 컴포넌트와 분리된 합성 데이터 검사 화면을 만든다. F0 router/main/preload/
트레이에는 연결하지 않는다. 1280px 이하 배치가 화면 정의서(본문 위)와 디자인 시스템(본문 아래)에서
다르므로, 구체적인 S04 화면 정의서의 본문 위 배치를 따른다. Calendar 미연결/차단 시
등록 성공을 표시하지 않으며 이번 화면에서는 OAuth 재동의를 시작하지 않는다.
S10 OS 알림·트레이·30초 수신 성능·실제 Google 등록은 이 검사의 통과 범위에 포함하지 않는다.
